# Learning 候选处理

只有以下信息进入 Learning：

- 用户明确纠正了当前实现口径。
- Review 已确认某个问题，并且现有正式规则没有覆盖。
- 多个真实任务重复出现同类偏差。
- 正式规则、专业 Skill 与项目事实发生冲突。
- 自动修复无法收敛或频繁需要用户确认。

先在 `coding-rules-learning.md` 查重。相同候选合并证据和出现次数，不创建近义条目。候选只保存脱敏摘要，不记录完整提示、源码、diff、密钥、Cookie 或业务敏感数据。

候选至少说明：

- 候选规则及稳定 ID。
- 脱敏后的任务证据和出现次数。
- 建议进入 Common、Java Skill 或 API Skill。
- 适用范围、合理例外及与正式规则的冲突。
- 状态保持为 `待确认`。

单次反馈可以登记候选，但不能直接晋升。只有经过真实任务验证并由用户人工确认后，才能修改 `coding-rules.md`、`coding-standards-java` 或 `api-design`；不通用或无收益的内容转为已拒绝迁移记录。
