# Java 完整规范

本文件保存跨项目 Java/Spring 规范的详细定义、适用条件和示例口径。涉及新模块、版本、分层、事务并发、性能或测试策略时读取；普通局部修改不加载。

目标项目的构建配置、现有架构和局部规则优先。本文中的示例来自不同版本和项目，不得在未确认兼容性时直接套用。

## 版本与项目事实

实现前读取 Maven 或 Gradle 配置，确认：

- Java 版本与编译目标。
- Spring Boot、Spring Framework 和 Jakarta/Javax 体系。
- Lombok、MapStruct、MyBatis/MyBatis-Plus 等实际依赖。
- formatter、Checkstyle、SpotBugs、PMD 或项目自定义检查。
- 测试框架和项目现有测试约定。

record 需要 Java 16+，sealed class 需要 Java 17+，部分模式匹配和 switch 能力需要更高版本。现代语法只有在目标项目支持且能提高可读性时使用。

## 命名与格式

| 对象 | 默认命名 |
| --- | --- |
| 类、接口、枚举、record | PascalCase |
| 方法、字段、参数、局部变量 | camelCase |
| `static final` 常量 | UPPER_SNAKE_CASE |
| 包名 | 全小写 |

方法名优先使用能表达业务动作或判断的动词短语，例如 `findOrderById`、`calculateAmount`、`isValidStatus`。避免 `data`、`flag`、`temp` 和无团队共识的缩写。

格式服从项目工具；没有工具约束时保持当前模块一致。成员顺序和缩进不使用跨项目固定值覆盖现有规范。

换行服从 `coding.avoid-mechanical-line-wrap`。Java 以 140 字符作为软参考线，不作为机械阈值；单个注解、单参数声明或结构清楚的调用略微超过参考线时可以保持单行，多参数或复杂表达式影响阅读时按参数或业务语义边界换行。

每个文件通常只放一个公共顶级类型。有独立语义的 DTO、枚举和公共类型使用独立文件；只在局部短暂使用的临时结构可以保留为内部类型。

## 类型、可变性与泛型

值对象和真正不可变的数据优先使用目标版本支持的不可变表达；普通 Java Bean、DO、DTO 和框架实体不强制整体改造成不可变对象。

- 能保持不变的依赖字段优先使用 `final`。
- 公共 API 暴露集合时，根据契约判断是否需要防御性复制。
- 不在单例 Bean 或静态字段中保存请求、任务、计数和失败明细等过程态。
- 使用泛型参数，避免原始类型；有明确复用价值时使用有界泛型。
- 魔法值在具有稳定业务语义时收口为常量或枚举，不机械常量化一次性局部值。

## Optional、null 与集合流程

可能缺失的查询结果可以使用 `Optional<T>`，但不盲目调用 `get()`，也不默认把 Optional 用作字段或参数。

Stream 适用于单向筛选、映射和汇总。以下场景优先使用普通循环：

- 同时修改业务状态。
- 收集多个副作用参数。
- 合并多组前后状态集合。
- 流水线需要复杂嵌套或依赖执行顺序。

集合天然可能一对多时，不默认取第一条；根据业务语义使用 `anyMatch`、`noneMatch`、分组或明确唯一性校验。

null、空集合和默认值在一条调用链中保持同一语义。外部协议类型和空值归一化优先在 gateway、repository 或 convert 边界完成。

## 异常、输入与安全

- 领域错误使用项目现有的业务异常体系，不通过异常 message 反向判断业务分支。
- 捕获技术异常时保留真实原因和有效上下文，不空 catch、不吞错、不做无意义包装。
- 宽泛 `catch (Exception)` 只在顶层边界、明确降级契约或项目既有模式允许时使用。
- 请求、消息、文件和第三方响应在信任边界校验；后续层不重复相同基础校验。
- SQL 使用参数绑定；动态标识符使用白名单。
- 源码和提交配置不保存真实密钥、Token、密码和私钥。
- 日志和对外错误不泄露凭据、敏感个人信息、SQL、内部路径和堆栈。

API 请求、响应和契约的详细要求由 `api-design` 承担，不在本规范重复维护。

## 分层与对象转换

沿用目标项目已有分层。项目可能包含 interfaces、application、domain、repository 和 infrastructure，但这不是跨项目强制目录模板。

职责参考：

| 分层 | 主要职责 |
| --- | --- |
| interfaces | Controller、协议接入和 Web 配置 |
| application | 用例编排、请求响应模型和事务入口 |
| domain | 领域模型、业务规则和领域服务 |
| repository | 数据访问与持久化实现 |
| infrastructure | 外部服务、技术组件、配置和工具 |

转换和中间对象必须承载协议隔离、业务语义、复用或复杂度收敛价值。简单 CRUD 在没有领域规则时允许直接 Req 转 DO，不为形式完整机械增加领域层。

复杂场景先准备业务数据，再一次性输出最终 DTO/VO；不把最终对象作为跨分支持续修改的过程态容器。

构造函数注入通常有利于测试和依赖不可变，但是否统一采用必须服从目标项目现状，不为更换注入方式扩大任务范围。

## Spring、事务与并发

事务边界围绕需要原子完成的状态变化设计，先确认：

- 哪些数据库写入必须共同提交或回滚。
- 外部调用、消息发送和缓存操作是否能参与事务。
- 异常类型是否会触发目标项目的回滚配置。
- 重试、异步或补偿是否会导致重复执行。

不因为方法名含 `update` 就机械添加事务，也不在存在多步一致性要求时省略事务。

并发、锁和线程池必须确认生命周期、上下文传递、超时、异常传播和资源释放。只有相互独立、性能收益明确且项目已有合适执行器时才并行查询。

长耗时 Job 的分布式锁、锁租期和拿锁失败语义属于候选规则，必须结合项目基础设施确认，不直接套用示例。

## 注解、监控与日志

Lombok、锁、日志和监控注解只在目标项目已经使用相应能力时采用。

- `@Data`、`@Getter`、`@Setter` 等注解要符合实体、继承和序列化约束。
- 分布式锁注解的 key、字段、租期和释放方式服从项目实现。
- `@Monitor` 等监控注解只用于项目认可的埋点位置，业务编码、SpEL 参数和标签复用项目口径。
- 日志说明阶段、业务标识和失败上下文，避免重复输出低信息量动作日志。
- 注释解释业务口径、兼容、顺序、历史原因和外部限制，不复述代码。

业务方法和关键私有业务方法的方法级说明服从 `coding.comments-explain-why`。Java 使用 Javadoc；入参、返回值或异常语义不直观时补充 `@param`、`@return` 和 `@throws`，简单辅助方法不机械添加。

## 查询、缓存与性能

性能优化必须有当前收益或证据：

- 查询只选择所需字段，但不为极小收益破坏既有映射和维护性。
- 避免明显 N+1、无界查询和大偏移分页风险。
- 缓存只用于读取频繁、口径稳定且失效策略明确的数据。
- Redis、本地缓存和多级缓存必须说明 key、TTL、一致性和降级行为。
- 并行查询必须使用项目认可的执行器并保留 MDC 等必要上下文。

不得为了“性能最佳实践”在没有测量和需求时引入缓存、异步或并行复杂度。

## 测试

测试框架和依赖服从项目事实。项目使用 JUnit 5、AssertJ、Mockito 或 Testcontainers 时复用现有模式，不为应用规范单独更换测试栈。

测试应：

- 以业务场景和预期行为命名。
- 使用清晰的准备、执行和断言结构，不要求机械添加 AAA 注释。
- 覆盖本次行为变化、失败分支和回归风险。
- 避免隐藏 sleep、真实时间竞争和执行顺序依赖。
- Mock 外部依赖而非被测核心逻辑，避免无必要的部分 Mock。
- 需要验证数据库或基础设施契约时使用项目已有集成测试方式。

固定 80% 行覆盖率不作为跨项目规则；覆盖率只能结合模块风险、项目基线和 CI Gate 判断。

## 常见代码异味

重点关注：

- 方法同时承担多阶段且没有清晰业务结构。
- 嵌套过深而可以用守卫条件表达。
- 长参数列表没有形成明确操作语义。
- 无语义 DTO、Resolver、Validator、Convert 或薄 Service。
- 静态或单例可变任务状态。
- 静默捕获异常或重复无信息包装。
- Stream 中隐藏状态修改和外部副作用。
- 已删除实现遗留无用方法、依赖和 import。

方法和文件长度只作为调查信号，不使用固定 50 行或 800 行阈值机械拆分。
